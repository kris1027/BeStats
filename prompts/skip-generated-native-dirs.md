# Skip generated native folders in the workspace scans

## Goal

`pnpm test` times out locally (9 tests in `security-boundary.test.ts`, 5000 ms) on any Mac that has run a local iOS build, because the workspace walk descends into `apps/mobile/ios/Pods` (~1.5 GB). CI has no `ios/` folder, so only local runs fail. Skip the generated native folders so the scans stay fast and green, without skipping any real code by name.

## Inspected code

- `apps/web/workspace-files.ts`: `workspaceFiles()` is the one walker every workspace scan uses; it skips folder names from `skipDirs` at any depth plus dotted folders.
- Callers: `security-boundary.test.ts` and `design-tokens-boundary.test.ts` (whole workspace), `lib/legal/boundary.test.ts` (`apps`, `packages`), `lib/region-boundary.test.ts` (web folders only).
- Other walkers (`private-actions-boundary.test.ts`, `catalog-lists`, `request-scope`, `cookie-boundary`, `with-v1`, core `purity.test.ts`) walk only web or core folders and never reach `apps/mobile`.
- `apps/mobile/.gitignore` lists `/ios` and `/android`; `apps/mobile/AGENTS.md` says they are generated by Continuous Native Generation and never edited by hand.

## Skills used

None needed (no schema, Supabase or UI work).

## Decisions and assumptions

- Exclude by workspace-relative path (`apps/mobile/ios`, `apps/mobile/android`), not by folder name, so a real folder named `ios` anywhere else is still scanned.
- Put the exclusion in `workspaceFiles()` itself rather than in each caller's `EXCLUDED_DIRS`: it applies to every scan through the shared walker, including the legal scan that only skips `node_modules` today, and a future scan inherits it. `EXCLUDED_DIRS` in the two root scans gets a JSDoc line pointing at it.
- Skipping is safe: these folders are gitignored, regenerated by `expo prebuild` from `app.json` and config plugins, and absent in CI; any secret or colour would have to come from committed config, which is still scanned.

## Expected files

- `apps/web/workspace-files.ts`: `GENERATED_DIRS` set of workspace-relative paths, skipped in `walk`; JSDoc explaining why.
- `apps/web/security-boundary.test.ts`, `apps/web/design-tokens-boundary.test.ts`: JSDoc on `EXCLUDED_DIRS` notes the generated native folders are skipped by the walker.
- `apps/web/workspace-files.test.ts` (new, small): the walker never lists a file under `apps/mobile/ios` or `apps/mobile/android`, but still lists `apps/mobile/src`.

## Requirements

- No file under `apps/mobile/ios` or `apps/mobile/android` is read by any workspace scan.
- A folder named `ios` or `android` elsewhere is still scanned.

## Security considerations

The service role, secret prefix and public-env scans keep covering every committed file; only gitignored generated output is skipped.

## Acceptance criteria

- With `apps/mobile/ios` present, `pnpm --filter @bestats/web exec vitest run security-boundary.test.ts` passes well under the timeout.
- `pnpm typecheck`, `pnpm lint`, `pnpm test` pass.

## Automated checks

`pnpm typecheck`, `pnpm lint`, `pnpm test`, plus the targeted vitest run above with a local `apps/mobile/ios` (symlinked from the main checkout's iOS build in this worktree, removed afterwards). No build needed (test-only change).

## Manual test steps

1. In a checkout that has `apps/mobile/ios` (run `npx expo run:ios` once, or use an existing build), run `pnpm --filter @bestats/web exec vitest run security-boundary.test.ts`.
2. Confirm it passes in a few seconds rather than timing out.
3. Run `pnpm test` and confirm every package is green.
