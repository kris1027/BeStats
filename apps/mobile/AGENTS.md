# apps/mobile

The BeStats iOS and Android app (`@bestats/mobile`): Expo SDK 58, Expo Router, NativeWind v5 and TanStack Query. It shares its rules with the web through `@bestats/core` and reads the catalog and the user's state only through `/api/v1` on the web project. Governed by spec [0033](../../docs/specs/0033-mobile-app-expo/index.md) (children 0035 and 0036); the root `AGENTS.md` sections 1 to 14 apply here too.

This is an Expo/React Native mobile application. Prioritize mobile-first patterns, performance, and cross-platform compatibility.

## Expo has changed — do not trust your training data

Expo ships breaking changes every SDK release. APIs you remember are likely renamed, moved, or removed. Before writing any code that touches an Expo, EAS, or React Native API:

1. Read the major version of the `expo` package in `package.json`.
2. Fetch the matching versioned docs: `https://docs.expo.dev/versions/v<major>.0.0/`
3. For anything else, fetch https://docs.expo.dev/llms.txt — an index of all Expo docs with corrections to common LLM misconceptions. Follow its links to the specific page you need; never answer from memory.

## Commands

Run these from `apps/mobile` (the repo uses pnpm; lint is Biome from the repo root, never `expo lint` or ESLint):

```bash
npx expo install <package>  # ALWAYS use instead of pnpm add for runtime deps: resolves SDK-compatible versions
npx expo start --dev-client # Metro for the development build
pnpm typecheck              # tsc --noEmit
pnpm test                   # jest-expo + React Native Testing Library v14
npx expo-doctor             # diagnose dependency and config issues
npx expo install --fix      # fix incompatible package versions
pnpm brand-icons            # rewrite the icon and splash PNGs from core's brand/mark.ts
pnpm grain                  # rewrite the page background's grain tile (seeded, so the same bytes)
```

From the repo root, `pnpm typecheck`, `pnpm test` and `pnpm lint` cover this app too. Run them before declaring any task done.

## Navigation & Routing

- Use **Expo Router** for all navigation. Routes live in `src/app/` — every file there is a screen, `_layout.tsx` files define navigators. Keep non-route code (components, hooks, utils) outside `src/app/`.
- Import `Link`, `router`, and `useLocalSearchParams` from `expo-router`.
- Docs: https://docs.expo.dev/router/introduction.md

## Building with EAS

Use EAS to build, sign, and submit the app in the cloud (`eas build`, `eas submit`) and to ship over-the-air updates (`eas update`) — no local Xcode or Android Studio required. Run EAS CLI as `npx eas-cli@latest <command>`; substitute that for bare `eas` in docs examples.
Docs: https://docs.expo.dev/eas/index.md

- The EAS project is `@kris1027dev/bestats` (`extra.eas.projectId` in `app.json`); bundle and package ID `com.kris1027.bestats`, which can never change after the first store upload.
- `eas.json` profiles: `development` (device dev client), `development-simulator` (iOS Simulator, needs no Apple developer account), `preview` (internal), `production`. Each has an EAS Update channel of the same name; `runtimeVersion` follows `version` (`appVersion` policy), so an update reaches only builds of that version. `eas update:configure` wrote `updates.url` and the `runtimeVersion` policy: change them only by rerunning it. The `preview` profile and its channel were added by hand; keep every channel equal to its profile name (`src/lib/native-intent.test.ts` checks it). Expo is in core's `PROCESSORS` because of these update checks. The release runbook is `docs/deploy.md` section 12.
- A development build loads its JavaScript from Metro on your Mac, so it reads `.env.local`; a store build needs the `EXPO_PUBLIC_*` values set in EAS.
- Personal iPhone build (free Apple ID, no EAS): `APP_VARIANT=personal` makes `app.config.ts` swap in `com.kris1027.bestats.personal` (the name stays "BeStats") and turn EAS Update off, so a free team never registers the store ID and the build never calls Expo. Production values go in the gitignored `.env.production.local`, which Expo reads only when bundling for production. Run `APP_VARIANT=personal npx expo prebuild --clean -p ios` (with `LANG=en_US.UTF-8`, or `pod install` fails), then `APP_VARIANT=personal npx expo run:ios --configuration Release --device <udid> --no-bundler`. The install stops opening after 7 days; rerun the last command. Plan: `prompts/mobile-personal-release-build.md`.

## Rules

- If `ios/` and `android/` directories do not exist, they are generated (Continuous Native Generation). Never create or edit them by hand — configure native behavior in `app.json` and config plugins.
- Expo Go only includes its bundled native modules. After adding a library with native code, the app needs a development build: `npx expo run:ios|android` locally, or `eas build --profile development`.
- Prefer recommended Expo modules over third-party libraries, and check your available skills before adding dependencies. Docs: https://docs.expo.dev/versions/latest/index.md

## Files

- `src/app/`: routes only. `_layout.tsx` is the root stack (the tabs, with `sign-in.tsx`, `sign-up.tsx`, `forgot-password.tsx` and `reset-password/app.tsx` as modals over them); `+native-intent.tsx` rewrites every incoming link through core's `isAppLinkPath` and sends anything else Home; `(tabs)/_layout.tsx` holds the native bottom tabs (Home, Search, Library, Account). The four tabs share one folder, `(tabs)/(index,search,library,account)/`, so each keeps its own stack; its `unstable_settings` anchors each stack, keyed by the bare group name (`search`, not `(search)`). Route paths mirror the web's: `movies|shows|games/[id].tsx` each open a list screen when the segment is a core list slug (`isCatalogListSlug`) and the title otherwise; `shows/[id]/season/[number].tsx` is the season screen; `account/delete.tsx` is pushed on the Account stack. The root layout wraps everything in `ToastProvider`.
- `src/screens/`: the screen bodies the routes render (Home, list, Search, movie, show, season, game, library, `account-screen.tsx` and `delete-account-screen.tsx`; `title-states.tsx` for a failed title read). `src/components/`: shared UI (poster card and grid, landing section, media switch, filters sheet, state panels with `SignedOutState`, `form-field.tsx` with `FormField` and `INPUT_CLASS` for every text field, `CatalogNotice`, `chevron-row.tsx` with `ChevronRow`, the one glass row with a `›` for Account's and About's rows), plus the tracking pieces: `tracking-gate.tsx` (Sign in to track, loading, read error with Retry), `score-sheet.tsx`, `toast.tsx`, `episode-row.tsx`, `season-nav.tsx`, `rating-line.tsx`, `cast-row.tsx` and `screenshot-row.tsx`.
- Movie, show and game screens scroll inside `TitleScroll` (`components/title-header.tsx`): with a backdrop, the artwork runs full bleed under a transparent native header that fades solid with the title and stretches on pull (1:1 with the content, never parallax; no stretch and an instant switch under Reduce Motion; under Reduce Transparency the header stays solid and the artwork starts under it); with none, the stack's solid header stays. It provides `OverBackdrop`, which `DetailHeader` reads to hang its poster over the artwork. It reads `HeaderHeightContext`, not `useHeaderHeight`, which throws outside a stack header. `components/title-details.tsx` holds `CrewLines` and `FactsPanel`, the web's, each line or fact only when the catalog has a value (prompts/mobile-look-title-pages.md).
- Title extras (`components/title-extras.tsx`, prompts/mobile-look-title-extras.md): the Trailer button opens `youtubeWatchUrl` (core) with `Linking.openURL`, never an embed; Where to watch, the age pill (a `DetailHeader` prop) and a movie's or show's More like this come from `/api/v1/{movies|shows}/{id}/extras`, whose country the server picks from the connection (the web's rule), and a game's More like this from `/api/v1/games/{id}/similar`. Each is its own query beside the title's, so a failed or slow extras read shows its own error line with Try again and never blocks the title.
- `components/swipe-row.tsx` is the only importer of `ReanimatedSwipeable`, and the root layout wraps the app in `GestureHandlerRootView` for it. Its action only calls the handler the row's visible button calls, so a swipe writes, toasts and buzzes exactly like the button; it is hidden from screen readers, which reach the same action through that button (decided 2026-11-23).
- `src/lib/catalog.ts`: the public catalog calls and `catalogKeys`, all under `CATALOG_QUERY_ROOT` (`"catalog"`), never the private root, so sign out keeps them and signed out browsing works. `src/lib/media-type.tsx`: the Shows, Movies, Games choice Home and Search share. `src/lib/search-results.ts`: `searchView`, the pure mapping from loaded search pages to what the screen shows. Search's title field is the native header search bar, set by the screen through `navigation.setOptions` (`headerSearchBarOptions`, with `MAX_QUERY_LENGTH` applied in `onChangeText`); a games search's Platforms filter reads `/api/v1/platforms` (`fetchPlatforms`) and opens `platform-picker.tsx` inside the filters sheet.
- `src/lib/account.ts`: `profileKey` (under `PRIVATE_QUERY_ROOT`), `useProfile`, `useSaveUsername`, `putUsername` and `deleteOwnAccount` (`POST /api/v1/me/account/delete`, resolving only on its 204). `src/lib/auth-errors.ts`: `authErrorMessage`, which reads a Supabase Auth error through core's `classifyAuthFailure`, the web's rule.
- `src/lib/env.ts`: `getPublicEnv()`, the only reader of `process.env.EXPO_PUBLIC_*` (literal property access, validated lazily). Values are public by design; no secret ever takes an `EXPO_PUBLIC_` name (`security-boundary.test.ts`).
- `src/lib/supabase.ts` and `session-storage.ts`: the one Supabase client, its session AES encrypted in AsyncStorage with the key in `expo-secure-store`; `AppState` starts and stops auto refresh. `getAccessToken()` is the token source. `refreshSession()` runs only in `refreshAfterUnauthorized()`, after a server 401, single flight and skipped when another call already rotated the token; never call it anywhere else (rotating refresh tokens can race and sign the user out). The session is stored under `SESSION_STORAGE_KEY` (`bestats-auth`); `signOutLocally()` is the only local sign out and deletes that entry itself when supabase-js refuses (2.116 returns an error and keeps the session when the expired session cannot refresh).
- `session-storage.ts` decodes the decrypted session with its own `utf8FromBytes`, never `aesjs.utils.utf8.fromBytes`, which breaks on 4 byte characters (an emoji in a Google display name lost the session). A key that no longer matches its ciphertext reads as no session (`session-storage.test.ts`).
- The client runs `flowType: "pkce"`, and `getSupabase()` calls `installWebCrypto()` (`src/lib/web-crypto.ts`, from `expo-crypto`) first, because Hermes has no `crypto.subtle` and supabase-js would fall back to a `plain` challenge. Keep that call before `createClient`.
- `src/lib/session.tsx`: `SessionProvider` and `useSession()`. Sign out and an expired session set the session to null themselves (never waiting for `SIGNED_OUT`, which a refused sign out never sends) and call `clearPrivateQueries()` (`src/lib/query-client.ts`): every `"me"` query and every mutation go, public catalog queries stay. Never `queryClient.clear()`: it cancels the reload of a query an open screen observes and leaves that screen spinning. Any `SIGNED_OUT` the app did not start (supabase-js ends the session itself when a refresh is refused after the account was deleted, the password reset or a global sign out elsewhere) sets the expired notice, so every sign out the app starts on purpose runs inside `signOutQuietly`, or it would show that notice too.
- `src/lib/api.ts`: `apiRequest()`, the only caller of `/api/v1`. It sends `X-BeStats-App-Version` from `app.json`'s `version`, parses every answer with its core schema, retries a `me` call once after a 401, then signs out with a visible notice. Errors are `ApiError` carrying the v1 code (`ApiErrorCode`: a core `V1ErrorCode` or `network`) and `reason`.
- `src/lib/movies.ts`, `shows.ts`, `games.ts`: the writes and restores per media type (`movies.ts` also reads the movie detail, keyed by `catalogKeys.movie`); `writeMovieIntent` and `writeGameIntent` pick the request for one core intent. `src/lib/tracking.ts`: `trackingKeys` (every private key starts with `PRIVATE_QUERY_ROOT`, `"me"`, defined in `query-client.ts` beside `clearPrivateQueries()`, so they are wiped together), the title and season state reads, `postRestore`, `useTrackingWrite` and `useUndoToast`.
- `src/lib/library.ts`: `libraryKeys` (under `PRIVATE_QUERY_ROOT`, invalidated by every tracking write; `useTrackingWrite` leaves a key under it to that one invalidation, since invalidating a page twice fetches it twice) and `useLibraryPage`, the infinite `/api/v1/me/library` read sent by route and type, never a page key. `src/screens/library-screen.tsx`: the Library tab, its page from the `type` and `path` params (`parseLibraryPathParam`, falling back to the type's first page); a failed first load or refresh shows the failed panel, never stale cards or the empty copy. `src/lib/library-card.ts`: `libraryCardView`, which takes every badge, date pill and game month line from core's `catalog/library-card.ts` (the web cards read the same rules), drawn by `components/library-card.tsx`. `src/lib/library-actions.ts`: `cardActionFor` (each card's quick action per library page, as the web's, its label from core's `LIBRARY_CARD_ACTION_LABELS`, which the web cards read too) and `useLibraryCardActions`, whose writes and Undos go through `useTrackingWrite` with the page's cached query as their state; `components/card-action-button.tsx` draws the button as its own pressable beside the card link, never inside it, with a 44 point tap area (prompts/mobile-card-quick-actions.md). A library card also carries the catalog card's long press menu and preview for its type, built from the page's own `entry.user` (no extra read) and written through `lib/title-writes.ts`; a failed card previews with no menu, a missing one neither (prompts/mobile-look-library.md).
- Catalog card actions (prompts/mobile-look-card-actions.md): `PosterCard` carries the user's marks and a long press menu once its screen's `useCardStates` (`src/lib/card-states.ts`) has read the cards' state, one `/me/titles` read per loaded page of `CARD_STATE_CHUNK` cards, seeded into each title's `trackingKeys.title`, so a card and its title screen share one cached state. A card's own query never goes stale (`useCardState`, `staleTime: Infinity`), so only the page read refreshes it and no card ever reads its title alone; `fetchTitleStates` in `src/lib/tracking.ts` builds every `/me/titles` request. Signed out, loading or after a failed read the card stays plain. The menus and marks come from `src/lib/catalog-card-actions.ts`, the marks placed by core's `movieCardStatus` and `gameCardStatus` (never a copy), so an Upcoming movie or an unreleased Want to play game shows the release pill as on the web; every write and Undo runs through `src/lib/title-writes.ts`, which the movie, show and game screens use too. Its Undo toasts close on the restore's own promise, never `mutate`'s per call `onSettled`, which TanStack skips once the card that asked has unmounted (a library card leaves its page on the server's answer). Both cards are a `CardLink` (`components/card-link.tsx`): the link, the iOS `Link.Menu` and `Link.Preview`, the Android alert and the screen reader actions in one place. `Link.Menu` and `Link.Preview` are iOS only: Android gets an `Alert` on long press, and both get `accessibilityActions`. The preview has no stack page background, so it takes `HEADER_BACKGROUND`, and `TitleScroll` sets no header options inside a preview (`useIsPreview`). `jest.setup.ts` stands in for the native link preview views, which Jest lacks.
- `src/theme/token-vars.ts` and `src/global.css`: colour tokens (see Styling).
- `src/components/launch-overlay.tsx`: `LaunchOverlay`, the cold start animation the root layout wraps around the app (`LaunchGate`, ready once the session has loaded). It alone calls `SplashScreen.hideAsync()`: one frame after its lockup is measured, or after 1000 ms if layout never comes, so never hide the splash anywhere else. Its sizes and times come from core's `brand/mark.ts`, which `scripts/brand-icons.mts` also renders the icon and splash PNGs from (with `sharp`), so after changing the mark run `pnpm brand-icons` and rebuild the native app (prompts/mobile-app-icon-launch.md).

## BeStats rules

- The phone never holds a catalog key and never runs a rule the server owns: the release gate, library placement and every write go through `/api/v1`. Pure rules come from `@bestats/core`, never a copy (spec 0033, shared contracts).
- An optimistic tracking state is computed by core's intent rules (`applyTrackingIntent` in `tracking/intent.ts`), mapped to and from the v1 title state; only the timestamp is the app's own.
- The UI only shows the server's confirmed state or an optimistic one it reverts with the error message; never a false success (root section 11). A screen covers loading, error with Retry, empty, missing image and signed out states.
- Every tracking write goes through `useTrackingWrite`: optimistic by core's intent rule, put back with the server's message on refusal (not after a 401, whose sign out already wiped the cache), then refetched. An Undo goes through `useUndoToast` and `postRestore`, its body the earlier write's own `cleared` answer; that restore is itself a `useTrackingWrite` write. Only `useTrackingWrite` fires the haptics in `src/lib/haptics.ts` (a medium impact on a confirmed write, the error buzz on a refused one, none after a 401), the only importer of `expo-haptics` (`ui-boundary.test.ts`). A failed haptic is swallowed in a store build and logged with `console.warn` in a development build, so a silent phone can be told apart from a missing native module.
- Outcomes show through `useToast()` (`components/toast.tsx`): each control keeps one toast of its own, replaced by its next one, and other controls' toasts stack (at most three), so a failure never wipes a pending Undo; a toast with Undo stays core's `UNDO_TOAST_MS`, and its timer pauses while the action is held, so an Undo or Retry pressed near the deadline is never lost.
- Copy comes from core's message files (`tracking/messages.ts`, `auth/messages.ts`, `search/messages.ts`) so both apps say the same thing.
- Password reset from the phone: `redirectTo` is `appResetRedirectUrl` of the `EXPO_PUBLIC_API_BASE_URL` origin, and the local Supabase allow list has only `localhost:3000/**`, so locally a reset works only from the simulator; a LAN IP build is refused (prompts/mobile-deep-links.md, decision 6).
- The catalog is public: no screen requires a session. Sign in is a modal that closes back to the screen that asked, and a session notice (an expired session) opens it from the root layout. Navigate from an effect with the `useRouter()` hook, never the global `router`: the global one is bound in a parent layout effect, so it throws on the first commit.
- The app is dark only: `Appearance.setColorScheme("dark")` in the root layout plus `userInterfaceStyle: "dark"` in `app.json`, so native chrome (glass tab bar, sheets, keyboard) never draws light.
- The query cache is persisted to AsyncStorage (`persistOptions` in `src/lib/query-client.ts`: 24 hours, `buster` the app version, never mutations), so the last loaded pages show offline. `clearPrivateQueries()` removes every `"me"` query from memory and the persisted entry from disk; sign out, an expired session, account deletion and a restore with no stored session (`wipePrivateCacheIfSignedOut`) all call it (AC-13).
- Offline: `src/lib/offline.ts` feeds NetInfo into `onlineManager`, so queries pause rather than fail, and `OfflineBanner` sits above the root stack. Writes use `networkMode: "always"`: an offline write fails, reverts, and its toast offers Retry (`network` errors only); nothing is queued.
- About (`account/about`, `screens/about-screen.tsx`) shows TMDB's and IGDB's logos from `assets/legal/`, byte for byte the web's files (`lib/legal-logos.test.ts`), with core's attribution text and its `PRIVACY_LABEL` and `TERMS_LABEL` links.

## Styling

- NativeWind `5.0.0-rc.1` with `react-native-css` `3.1.0-rc.1`, pinned exactly, with this app's own Tailwind `4.1.12`, `@tailwindcss/postcss` `4.1.12` and `lightningcss` `1.30.1` as NativeWind's setup asks. The web keeps its own Tailwind; don't unify them. rc.1 was tested by NativeWind on Expo 57; it runs on our Expo 58 (checked in the simulator), but recheck on every SDK or RC bump. Uniwind is the spec's named fallback.
- No colour literal here (`design-tokens-boundary.test.ts`; build a translucent token colour with `tokenColorAlpha`, never `rgba(`). `global.css` names each colour token as `--color-x: var(--bs-color-x)`, and `TOKEN_VARS` supplies the values from `@bestats/core/tokens.generated` through `VariableContextProvider` in the root layout. After `pnpm tokens` adds a colour, add its line to `global.css` (`token-vars.test.ts` fails until you do). React Native cannot draw oklch, so `pnpm tokens` also writes each oklch token as sRGB hex (`TOKENS_SRGB`), which `TOKEN_VARS` and `tokenColor` prefer. The radius scale reaches `global.css` the same way, worked out from the web's `calc()` by `lengthToken`.
- The look is the web's visual language with a native layout (feature 29, [prompts/mobile-web-parity-foundation.md](../../prompts/mobile-web-parity-foundation.md)). Every glass surface is `GlassPlate` (`components/glass/plate.tsx`): blur only on iOS, opaque on Android, under Reduce Transparency (`use-frosted.ts`, live) and inside `PlateSolid`; its sheen, the SVG `Rim` and the shadow come from `GLASS`, which `pnpm tokens` copies from the web's `@utility` rules. Only `components/glass/` imports `expo-blur` (`src/theme/ui-boundary.test.ts`).
- Every stack draws `PageBackground` (the web's layers, still, never animated) under each screen through `screenLayout` and `STACK_SCREEN_OPTIONS` in `src/theme/stack-options.tsx`; screens stay transparent, so never give a screen root `bg-background`. A React Native `Modal` gets no `screenLayout` and draws `PageBackground` itself (`filters-sheet.tsx`). A screen with an iOS large title cannot take that layer, since UIKit tracks only a scroll view first in the screen's view chain: the tab stacks draw `PageBackground` once behind their screens, with a transparent theme background, and `tabScreenLayout([...])` leaves the named screens bare (Search and Library). Such a screen also needs a translucent header (`headerTransparent`, `largeTitleScreenOptions(title)`), draws every state inside a scroll view so none sits under the bar, and shows its pull spinner only for a pull the user started (tied to a background refetch, iOS leaves the list inset open), because on iOS 26 and later react-native-screens insets a screen under an opaque bar itself and the title then never collapses (prompts/mobile-look-search.md). The grain is `assets/images/grain.png`, written by `pnpm grain`.
- Text is Inter, embedded by the `expo-font` plugin in `app.json` (`assets/fonts/`, with `OFL.txt`), so a font change needs a native rebuild. React Native text inherits no font: import `Text` and `TextInput` from `@/components/text`, never from `react-native` (`ui-boundary.test.ts`). Cap Dynamic Type with `maxFontSizeMultiplier` only on fixed height controls and on text whose width is fixed by its artwork (a poster card's title and year, `CARD_FONT_SCALE_CAP` in `src/theme/font-scale.ts`). A row of a title and a link stacks at the accessibility text sizes (`isAccessibilityTextSize`, Home's section headers), so the title wraps on whole words (prompts/mobile-large-text-titles.md).
- Icons come only from `@/components/icons`: the lucide icons the web uses, re-exported, and the web's tracking icons ported as `react-native-svg` (`icons/tracking-icons.tsx`). Never import `lucide-react-native` elsewhere (`ui-boundary.test.ts`); add a new icon to the barrel.
- Fully rounded controls take `PILL_RADIUS` and cap their labels with `PILL_FONT_SCALE_CAP`, both from `src/theme/pill.ts`, never a literal. The personal score's plate and cyan rim travel together as `SURFACES.score` (`glass/plate.tsx`); a score control spreads it (`GlassButton score`) rather than picking plate and rim one by one.
- A system accessibility setting (Reduce Transparency, Reduce Motion) is read through `createAccessibilityFlag` (`src/lib/accessibility-flag.ts`): read once, then followed live with one listener for the whole app.
- Reduce Transparency is `useReduceTransparency` (`src/lib/reduce-transparency.ts`), read by `useFrosted` and the title header.
- Reduce Motion is `useReduceMotion` (`src/lib/reduce-motion.ts`), shared by the skeleton pulse and the title header; never read it through Reanimated's `useReducedMotion`, which reads the setting once.
- Metro rewrites `tsconfig.json` to include `nativewind-env.d.ts` on start; keep that change.

## Tests

- Jest with the `jest-expo` preset and React Native Testing Library v14 (always `await render(...)`), set up in `jest.setup.ts` (native module stand ins such as AsyncStorage). Screens render through `renderRouter` from `expo-router/testing-library`.
- `jest.mock` factories may only reference variables named `mock…`.
- Reanimated and `react-native-worklets` are replaced in `jest.setup.ts` by `src/test-utils/reanimated-mock.ts`, since Reanimated's own mock loads a runtime jest-expo cannot run; animation durations follow Jest's fake timers. A `renderRouter` test that mounts the root layout stubs `@/components/launch-overlay`, because expo-router's helper swaps in its own Reanimated mock.
- `renderRouter` loads expo-router's testing mocks, which mock Reanimated with `react-native-reanimated/mock`; `moduleNameMapper` in `package.json` points that path at the same stand-in, or every title screen test gets an empty module. `jest.setup.ts` also stubs Gesture Handler: a swipeable renders its row with its actions beside it, found with `includeHiddenElements: true`, since they are hidden from screen readers.
- Title screen tests use `src/test-utils/title-harness.tsx`: `createApiMock()` answers `apiRequest` by method and path and records each call, so a test asserts the exact route and body a write sends; an unexpected call rejects. Wire it with `jest.mock("@/lib/api", …)` calling `mockApi.handle`.
- A test that imports the root `_layout.tsx` mocks `../global.css` (`jest.mock("../global.css", () => ({}))`), since Jest cannot parse it.
- Jest loads lucide's CommonJS build through `moduleNameMapper` in `package.json`; keep that mapping (and its path) when you upgrade lucide.
- TypeScript 6 loads no global types by default, so `tsconfig.json` lists `jest` and `node` in `types`.
- NativeWind classes are not compiled to styles under Jest, so `toHaveStyle` never sees a `className`; a test of a layout switch reads the element's `className` instead (`landing-section.test.tsx`).
