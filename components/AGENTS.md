# AGENTS.md — the UI foundation

Every shared piece of interface lives here. The theme it reads from lives in [`app/globals.css`](../app/globals.css), which is the only file allowed to hold a colour value. Governed by spec [0004](../docs/specs/0004-design-system-and-ui-foundation/index.md), whose `rationale.md` holds the original token inventory and the contrast audit.

**The UI reference is the shipped interface plus `/showcase`.** The `design/` folder of reference artboards was removed on 2026-10-06. Reuse existing components and patterns; a screen with no precedent gets its layout described in its plan and approved before it is built (root AGENTS.md section 3).

## The plate rule

A glass surface on its own is close to invisible over artwork. Near white text on the bare glass gradient over a light poster measures 1.59:1.

So: **plate first, then glass, then rim.** Off posters the plates are frosted ([prompts/frosted-glass.md](../prompts/frosted-glass.md)): see-through enough to show the page background, and always blurred so it stays soft behind the text. Anything over artwork sits inside `plate-solid`, which makes every plate in it opaque again: the poster card's badge and control slots, the skeletons and the quick search placeholder tiles. A new surface over a poster goes in a `plate-solid` slot rather than choosing its own plate.

The rule is enforced by the components that own a glass surface (`GlassPill`, `PosterCard`'s badge and control slots, `MobileMenuSheet`, `StatePanel`), never by the `glass` utility itself. That is deliberate: `/showcase` renders the plate-less case beside the correct one, so the rule stays visible rather than becoming folklore. If you write `glass` without a `glass-plate-*` alongside it, you are opting out of legibility on purpose.

## Tokens and utilities

All values live in `app/globals.css`, split across four blocks: `@theme inline` (the shadcn semantic remap and the radius scale), `@theme` (product tokens, which become real utilities such as `text-rating-tmdb` and `rounded-panel`), `:root` (the semantic values themselves), and the `@utility` definitions.

- **Three colours carry meaning and nothing else may borrow them**: `--color-rating-tmdb` amber is always a community rating, TMDB's or, on a game, IGDB's (spec 0025, AC-4), `--color-score-personal` cyan is always the user's own score, `--color-status-planned` green is always Planned. One deliberate exception, chosen by the owner on 2026-10-11: the selected navbar tab (`glass-selected-personal`) is lit in the personal cyan. The page background has its own warm tokens (`--color-page-*`, with their strengths in `--page-*-alpha`), which are for the background and the landing's glows and orbs only; no surface or text may use them, and its amber blob is not the rating amber ([prompts/warm-page-background.md](../prompts/warm-page-background.md)). The focus ring deliberately uses none of them.
- **Five plates**, each a frosted colour plus its blur: `glass-plate` for controls and badges (65%, 12px), `glass-plate-panel` for panels (60%, 20px), `glass-plate-sheet` for the dialog and menu sheet over their dimming backdrop (75%, 24px), `glass-plate-float` for what floats with no backdrop, the popover, quick search panel and toasts (90%, 24px), and `glass-plate-score` for the personal score badge (65%, 12px). The opacities are the `--frost-*` tokens; [`app/glass-contrast.test.ts`](../app/glass-contrast.test.ts) recomputes 4.5:1 for every text colour over each plate's worst background, so lower one only if that still passes. `prefers-reduced-transparency: reduce`, `prefers-contrast: more` and a browser without `backdrop-filter` get opaque plates and no blur. The selected utilities always paint the solid plate (`--glass-plate-solid`). The glass gradient's sheen tops out at 12% white; brightening it costs the frosted plates their contrast.
- **Surface utilities**: `plate-solid` (opaque plates and no blur for the element and everything inside it), `glass` (plate plus gradient plus rim), `glass-selected` (the brighter active variant), `glass-selected-personal` (the selected navbar tab, tinted from the personal score cyan, with `text-on-personal` dark text for contrast), `plate-rim` (plate and rim, no gradient, for surfaces that should read as an absence: the missing poster tile and the skeletons, which also carry `plate-solid`, because a rim shows through a frosted plate), `rim` (the bare gradient stroke over artwork). Pick the rim colour with `glass-rim` or `glass-rim-score`.
- `rim` masks its own padding box out, so it clips everything the element paints. It belongs on an empty decorative overlay, never on an element with content or a background of its own.
- The rim uses the two layer background technique: plate gradient on `padding-box`, rim gradient on `border-box`, over a transparent 1.5px border. Not `border-image`, which ignores `border-radius`.
- **No component writes a colour literal.** [`design-tokens-boundary.test.ts`](../design-tokens-boundary.test.ts) walks the repository and fails the suite if a token hex, a Geist reference, or a dark variant appears outside `globals.css`, in the shape [`security-boundary.test.ts`](../security-boundary.test.ts) already established for the service role key.

## Conventions

- **Server Components by default.** The only client boundaries are `layout/media-type-tabs.tsx`, `layout/brand-link.tsx`, `layout/mobile-menu-sheet.tsx`, `layout/library-nav.tsx` (rendered only inside the request scoped `AccountSlot`, spec 0008), `layout/page-background-motion.tsx` (the background's motion), and the three shadcn primitives that need state (`ui/dialog.tsx`, `ui/toggle.tsx`, `ui/toggle-group.tsx`). None reads a server dynamic API, so routes still prerender under `cacheComponents`. Adding a client boundary in the shell is a decision, not a convenience.
- **Selection comes from the URL**, not client state. `MediaTypeTabs` reads `usePathname`: the catalog and title pages light their own tab, and pages about neither catalog (`/account`, `/privacy`, `/terms`, the auth pages, `/showcase`, the 404 page) render no tabs, no search and no Library links in the bar ([prompts/hide-tabs-without-type.md](../prompts/hide-tabs-without-type.md)); the mobile menu keeps them there, previewing the catalog viewed last, since it is the whole of mobile navigation ([prompts/mobile-navigation.md](../prompts/mobile-navigation.md), decision 7). On the library routes and `/search` it also reads `?type=` through `useSearchParams`; on `/search` each tab links to the same page with the other type (feature 22), and on a library page to the matching page of the other tab, Playing to Upcoming (prompts/library-page-urls.md). That read happens only on those paths and in its own Suspense boundary, inside `layout/page-media-type.tsx` (`WithPageMediaType`, which `BrandLink` uses, and `WithLibraryTypedPage`, which renders nothing on a page with no type and which the tabs, `LibraryNav` and `NavbarSearch` use, following `libraryType`, so they show on games pages too, spec 0029). It carries no `"use client"` of its own, so it adds no boundary to the list above. Never call `useSearchParams` unconditionally in the shell, or every route loses its prerendered shell. On a route with a dynamic param `usePathname` suspends at prerender time, so `Navbar` wraps the tabs in Suspense with `MediaTypeTabsView selected={null}` (same control, nothing lit) as the fallback. Keep that boundary, or `/movies/[id]` loses its static shell (spec 0006). The Library links carry the current page's type, so a tab chosen on `/movies` is still selected on its library pages. The logo (`BrandLink`) links to the page's catalog, and on a page with no type to the last one viewed, kept in `localStorage` as a per browser convenience that never lights a tab ([prompts/logo-follows-media-type.md](../prompts/logo-follows-media-type.md)). It has its own Suspense boundary for the same dynamic route reason.
- **A retry is a full page load.** `RetryLink` is a plain `<a>`, not `next/link`, so the client router cache cannot replay the failure the visitor is retrying past (spec 0006, AC-10).
- **Focus** is a 2px `#F6F7F8` outline at 2px offset on `:focus-visible` only, driven by `--ring` in the base layer. Do not restate it per component.
- **Backdrop blur** comes with the plate utilities (`--blur-control`, `--blur-panel`, `--blur-overlay`, no saturation), so never add `backdrop-blur-*` to a frosted surface yourself. `--blur-glass` (16px) remains for the dialog backdrops and the poster badge slots. Only the outermost large surface frosts: a highlighted row or panel inside a panel takes no plate class of its own. Small controls inside a panel keep theirs; blur cost follows area, and a 22 episode season page held 120fps while scrolling over the animated background.
- **The navbar is transparent and not sticky.** It has no background, border or blur and scrolls away with the page: pinned over scrolling content, a transparent bar is unreadable. Do not make it sticky again without giving it a background. It is `relative z-20` so a title page's backdrop can pull up behind it (`DetailHero` and its skeleton subtract `--navbar-height`), under a `backdrop-scrim` that holds the artwork at 75% black across the bar so its text and frosted controls keep their contrast. If the bar's padding, gap or rows change, change `--navbar-height` in `globals.css` with it; `navbar.test.tsx` fails until they match, and `app/glass-contrast.test.ts` checks the scrim's shade. Every control in it is 40px tall at every width: the `bar` and `icon-bar` button sizes, `h-7` tabs inside a pill padded so tab, padding and the 1.5px rim add up to 40px, and an `h-10` search field. The `hit-area` utility (and `hit-area-tab` for a tab) stretches each tap area back to 44px, so the touch rule still holds.
- **The page background** (`layout/page-background.tsx`, rendered first in `<body>` by the root layout) is fixed at `-z-10`, `aria-hidden` and `pointer-events-none`. Its layers are plain CSS utilities in paint order, `page-gradient`, `page-blob-red`, `page-blob-amber`, `page-blob-deep`, `page-stripes`, `page-wash`, `page-vignette` and `page-grain`, all in the prerendered HTML, so the still background is the first paint. `PageBackgroundMotion` runs one `requestAnimationFrame` loop over the `data-page-*` layers: the blobs drift over time, everything slides with scroll progress, and only a mouse leans it. It stops in a hidden tab, never runs under reduced motion, and resets every layer when that setting turns on. No layer uses `filter: blur()`; a blob fades inside its own gradient, so nothing large is refiltered under the frosted plates. Nothing caps a pixel at runtime: [`app/page-background-contrast.test.ts`](../app/page-background-contrast.test.ts) stacks the brightest pixel the layers and the landing's glow and orb can reach and holds `text-muted-foreground` at 4.5:1 over it, so raising a `--page-*-alpha` fails there first. Nothing in the shell may paint an opaque full page background over it.
- **A dead end is a bug.** `StatePanel`'s `error` and `signed-out` variants cannot render without an action. The discriminated union makes it a type error and the component throws if the type is bypassed.
- **Touch targets** are 44px on mobile and 36px on desktop, the `touch` and `sm` sizes in `buttonVariants`. A control drawn smaller than 44px on mobile carries `hit-area` instead (root AGENTS.md section 3). One accepted exception: the footer's `kris1027` credit link has a 36px tap area, because 44px would mean taking taps from the legal links above it or widening the gap and moving the line.
- Posters render through `next/image` with `fill` inside `aspect-[2/3]`, using the `sizes` of the `PosterGrid` preset it sits in. `catalog` (every title grid) steps 2, 3, 4 and 6 columns (no 5, so the 24 title page, `GRID_PAGE_SIZE` in `lib/catalog/grid-page.ts`, fills every row) and a wide screen card stays near the home row card's 180px; `wide` (the season grid only) keeps 2 and 4 (spec 0022). Each preset's columns, `POSTER_GRID_SIZES` and `POSTER_GRID_EAGER` in `poster-grid.tsx` change together, and `poster-grid.test.tsx` recomputes the sizes. `POSTER_SIZES` in `poster-card.tsx` is the `catalog` value. The grid is capped at 1200px and centred.
- A missing poster renders the fallback tile at an identical footprint, so the grid never shifts. Never invent a placeholder image or placeholder metadata.

## Layout

- `components/ui/` holds the shadcn primitives, generated by the CLI then restyled to the glass system. Regenerating one overwrites the restyle, so diff before you accept it.
- `components/layout/` holds the app shell pieces. The navbar ships only its signed out form; the signed in variant arrives with feature 6 and must not be built by reading a client supplied identity.
- Everything else at the top level is a content piece: `glass-pill`, `rating-badges`, `poster-card`, `poster-grid`, `state-panel`, `skeleton`, `pagination-links`, `retry-link`.
- `components/movie/` holds the movie page pieces (`MovieHero`, `MovieOverview`, `CastRow`, `MovieDetailSkeleton`), all Server Components. Feature 10 should reuse their structure for TV rather than design a second page (spec 0006).
- `components/catalog/` holds the title page sections both `/movies/{id}` and `/shows/{id}` share (spec 0022): `title-details.tsx` (crew and Facts, from the detail read), and `title-extras.tsx`, `where-to-watch.tsx` and `trailer-button.tsx`, fed by the separate extras read. The extras sections stream in their own Suspense boundary and read the visitor's region there through `getVisitorRegion()` (`lib/region.ts`), never in the shell. The trailer iframe (`youtube-nocookie`) mounts only while its dialog is open.
- `components/catalog/landing/` holds the `/movies` and `/shows` landing sections, all Server Components except `landing-parallax.tsx` (`LandingParallax`), the landing's one motion island, and `hero-picture.tsx` (`HeroPicture`), client only because `getImageProps` calls the client-side image loader; it renders the hero's poster below `lg` and backdrop from it as one `<picture>`. Both sit outside the shell. It writes only inline transforms to the `data-*` nodes the sections render, so every card and link stays server HTML. It runs at every width, with distances scaled down below `md`, Popular turned into a sticky deck of pairs below `md` (`data-deck`, decision 13), and native swipe rows and still grids only under reduced motion ([prompts/mobile-landing-parallax.md](../prompts/mobile-landing-parallax.md)). It and `layout/page-background-motion.tsx` share `startMotionLoop` (`lib/motion/loop.ts`), which owns the reduced motion stop, the mouse-only lean, a viewport height that ignores a phone's address bar (`100svh`, passed to `tick`; never read `innerHeight` for scroll positions) and the opt-in `idle` mode the landing uses; a new motion loop uses it too.
- `/games` renders the same landing (spec 0028). Each media type's card and hero slots come from `LANDING_SLOTS` in `landing/landing-badge.tsx`; since G8 the `game` entry carries the status badge, the controls and the year `meta` (spec 0030), so change a game slot there, not as a branch in a card. A list page's error and empty panels live in `catalog/list-panels.tsx`, free of any read, so `/showcase` renders the real ones; each names its catalog through `CATALOG_SOURCES` (`lib/catalog/media-type.ts`), and a catalog failure is recognised only by `isCatalogError` (`lib/catalog-errors.ts`).
- `components/library/` holds the private library pages (spec 0020; prompts/game-coming-soon.md), each at a route named for it (`LIBRARY_PAGE_PATHS`, prompts/library-page-urls.md). A route file passes its path to `LibraryHeading`, `LibrarySection` and `libraryPageMetadata`, which find the page with `libraryPageAt(path, type)`. Each page is named per tab by `libraryPageName` (`lib/catalog/library-list.ts`): `LibraryHeading` streams its text through `WithPageMediaType` behind a placeholder bar and `lib/catalog/library-metadata.ts` builds the title, so no component writes a page name as a literal (prompts/library-page-names.md). `LibrarySection` reads one tab per request; show cards are Server Components (`watchlist-show-card.tsx` streams its season read per card, `show-cards.tsx` holds the Upcoming and Watched cards), and the client pieces, `library-grid.tsx` (movies), `mark-next-watched-button.tsx` and `missing-show-card.tsx`, sit outside the shell, so the shell's client boundary list above is unchanged. `ids.ts` is the one home of the focus ids the server cards and those client controls share. Show tracking writes from any surface go through `components/tracking/use-show-tracking.ts`, which owns the Stop tracking Undo. The games tabs (spec 0027) are `game-library-tab.tsx` (server), `game-library-grid.tsx` (client, the movie grid's `useOptimistic` order copied on purpose, so a removal fix may need making in both; the focus order after a removal is shared through `use-removal-focus.ts`) and `game-library-card.tsx`; their Undo toast is the plain `showGameUndo` in `components/tracking/use-game-undo.ts`. `library-error-boundary.tsx` (`catchError`) wraps each page's streamed section, below the heading, so `redirect()` still passes through.
- **The mobile navigation** (below `md`, [prompts/mobile-navigation.md](../prompts/mobile-navigation.md)) is one bar row, the wordmark and the menu button, for everyone. `layout/mobile-menu-sheet.tsx` is the full screen menu: search (`QuickSearch variant="overlay"`), a SHOWS | MOVIES | GAMES toggle that changes the page as the desktop tabs do (`mediaTabHref` in `layout/media-type-tabs.tsx`, the one place a tab's destination is worked out), closing the menu signed out and keeping it open on the new tab's rows signed in, and that switches only the search's type in search mode ([prompts/mobile-menu-tabs-navigate.md](../prompts/mobile-menu-tabs-navigate.md)), the library rows (`LibraryNavView variant="sheet"`, each with its card mark) and the account block. `AccountSlot` renders the signed in block on the server (`layout/mobile-account-block.tsx`: the Account row and Sign out) and passes it as `account`, or passes null, which means Sign in and no rows, so the client never decides who is signed in. The toggle is the shared `ui/toggle-group.tsx` in its `personal` variant, over `MEDIA_TABS` from `layout/media-type-tabs.tsx`. Tapping or typing into the field gives search the whole screen, while tabbing past it does not, so the keyboard still reaches the rows; Cancel brings the menu back with focus in the field. There is no separate mobile search overlay any more. Signed in, the desktop row (library links, account, Sign out) needs about 1460px on games, so between `md` and `xl` the desktop slot shows the same menu button instead, the full row from `xl` and the account name from `2xl`; the search field has a width per breakpoint (240px or 360px, shrinking to 160px only rather than overflow) so the slot streaming in never resizes it, and `hiddenFrom` closes an open menu when its button's breakpoint is crossed. While the session is read, `layout/account-slot-skeleton.tsx` draws the footprint of the controls that arrive at each width.
- `components/layout/site-footer.tsx` renders under every route from the root layout and must read no request state (`app/layout-purity.test.ts`). It is flat (no glass, no border) and carries no email address. Its credit line links `OPERATOR_HANDLE` to `OPERATOR_GITHUB_URL`, both from `lib/legal/operator.ts`. `components/legal/` holds the reading column and helpers `/privacy` and `/terms` share; use `LEGAL_LINK_CLASS` for any link in legal text (spec 0017).
- The card marks are explained once, by `layout/icon-key.tsx`, the footer's first row on every route; there is no per page legend. A new mark adds its entry there, and a new badge must reuse `GlassPill` rather than re-derive it.

## Checking your work

`/showcase` renders every token, primitive, badge and state in one place, including the plate rule demonstration. It calls `notFound()` under `NODE_ENV === "production"`, so it is a static 404 in a production build while still rendering under `next dev` and Vitest. It only earns its keep if you update it alongside what you change; a stale showcase is worse than none.

Tests here cover keyboard operation, visible focus, roles, and the dialog's focus trap and focus return. `pnpm test` runs them.
